## What this shows

- In **22.6%** of merges where both branches touched the same code file, both branches edited the **same function**, and Git reported **no conflict**. These are exactly the cases Preflux flags as `conflict-same-function` (high).
- After such silent same-function merges, a bug-fix commit touched one of those files within 30 days in **25.5%** of cases, compared with **34.3%** for other overlapping merges.
  So this data does **not** show that silent same-function merges lead to more bug fixes. Preflux therefore presents them as a **coordination** signal ("someone else is changing this function"), not as a bug prediction.

## Limits

- "Fix within 30 days" uses the commit-message fix regex (as SZZ does): it shows correlation, not proof that the merge caused the bug.
- Only merge commits are visible. Squash and rebase merges leave no two-parent commit, so these numbers undercount how often parallel edits happen.
- Function matching is by name per file; see docs/conflicts.md.
- The "API changed vs. new calls" counts (24, mostly express) match calls by function name and haven't been checked by hand; some may be unrelated functions with the same name.
- 51 silent same-function merges is a small sample, so the follow-up-fix percentages are noisy.
